# WP MCP

**هوش مصنوعی سایت‌های وردپرس شما را از صفر تا صد اداره می‌کند، فقط با MCP.** بدون ویرایشگر بصری. هوش مصنوعی ۱۴ ابزار مستند (۱۱۷ عملیات سایت) برای طراحی، سئو، نگهداری، افزونه‌ها، محتوا، فروشگاه و فرم‌ها دارد؛ با سطح دسترسی، تأیید دومرحله‌ای، بازگردانی (undo) و لاگ فعالیت.

🇬🇧 [English guide](README.md)

```
Claude.ai / Claude Code / Cursor / هر کلاینت MCP
              │  Streamable HTTP بدون session · OAuth 2.1 + PKCE · کلید API
              ▼
      ┌────────────────────┐      HTTPS امضاشده (HMAC)       ┌──────────────────────┐
      │  gateway (Node)    │ ──────────────────────────────► │ افزونه WP MCP Bridge │  سایت A
      │  توکن، سطح‌ها،     │ ──────────────────────────────► │  (PHP 8.1+، سبک)     │  سایت B
      │  rate limit، لاگ   │                                 └──────────────────────┘  سایت C
      └────────────────────┘
```

## چرا gateway + افزونه

| پرسش | پاسخ |
|---|---|
| یک اتصال برای چند سایت؟ | بله. کلاینت هوش مصنوعی **یک بار** به gateway وصل می‌شود. هر ابزار پارامتر `site` دارد و هر نتیجه نام سایت را تکرار می‌کند. |
| اتصال پایدار؟ | توکن‌ها در gateway (SQLite) نگهداری می‌شوند نه `wp_options`. توکن دسترسی ۱ ساعته است ولی **refresh token چرخشی و ۱۸۰ روزه** است؛ قطع شدن پاسخ refresh تحمل می‌شود و آفلاین بودن یک سایت، ورود هوش مصنوعی را باطل نمی‌کند. |
| ایمن؟ | چهار سطح (`read` < `draft` < `live` < `admin`) که دو بار اعمال می‌شود (gateway و افزونه)، سقف سطح برای هر سایت، تأیید دومرحله‌ای عملیات مخرب، undo برای بیشتر تغییرات، محافظ SSRF و هشدار محتوای غیرقابل‌اعتماد. |
| سنگین برای وردپرس؟ | خیر. افزونه فقط یک endpoint امضاشده و handlerهاست و تا زمانی که gateway را جفت نکنید کاری نمی‌کند. |

جزئیات: [docs/fa/architecture.md](docs/fa/architecture.md)

## شروع سریع

۱. **اجرای gateway** (Node 22.13 به بالا؛ Docker هم هست، [docs/fa/install.md](docs/fa/install.md)):
   ```bash
   cd gateway && npm ci && npm run build
   WPMCP_PUBLIC_URL=https://mcp.example.com npm start
   ```
   به `/admin` بروید، توکن راه‌اندازیِ چاپ‌شده در لاگ را وارد و رمز مالک را بسازید.

۲. **نصب افزونه** روی هر سایت: پوشه `plugin/wp-mcp-bridge` را zip کنید، در *افزونه‌ها ← افزودن* آپلود و فعال کنید. در *ابزارها ← WP MCP Bridge* یک کد جفت‌سازی بسازید.

۳. **اتصال سایت** در پنل gateway (بخش *Connect a site*: آدرس سایت + کد جفت‌سازی). یک نام یکتا بدهید.

۴. **اتصال هوش مصنوعی**: Claude.ai (*Settings ← Connectors ← Add custom connector ← `https://mcp.example.com/mcp`*) یا Claude Code:
   ```bash
   claude mcp add --transport http wp https://mcp.example.com/mcp
   ```
   جزئیات و کلید API: [docs/fa/connect.md](docs/fa/connect.md)

## هوش مصنوعی چه کارهایی می‌تواند بکند

| ابزار | حوزه |
|---|---|
| `site` | شروع: سایت‌های وصل‌شده، نمای کلی سایت، «من کیستم»، schema هر عملیات |
| `content` | نوشته، برگه، انواع سفارشی، دسته/برچسب، نظرات، نسخه‌ها |
| `design` | قالب‌ها و بخش‌ها (هدر/فوتر)، CSS در بخش‌های نام‌دار، توکن‌های طراحی، منو، صفحه اصلی، برندینگ، پوسته‌ها و فایل‌های پوسته |
| `media` | کتابخانه، آپلود (base64 یا URL با https)، متن جایگزین |
| `seo` | فیلدهای Yoast / Rank Math / SEOPress / داخلی، ممیزی صفحه، robots.txt، سایت‌مپ، ریدایرکت، JSON-LD |
| `inspect` | HTML واقعی رندرشده، درخت عناصر، استایل‌شیت‌های هر صفحه |
| `maintain` | سلامت، به‌روزرسانی، بکاپ/بازگردانی دیتابیس، لاگ، کش، پاکسازی دیتابیس، جستجو-جایگزینی، cron، حالت تعمیر |
| `plugins` | فهرست، جستجو، نصب، فعال/غیرفعال، حذف |
| `users`، `options` | کاربران و نقش‌ها (admin)، گزینه‌های سایت با پنهان‌سازی رمزها |
| `rest` | کشف و فراخوانی **هر** مسیر REST (ووکامرس، فرم‌ها، سفارشی) با سطحِ مشتق‌شده از مسیر و متد |
| `shop`، `forms` | محصولات/موجودی/کوپن/سفارش ووکامرس؛ CF7 و Gravity و WPForms و Fluent Forms |
| `activity` | چه کارهایی شده (gateway و سایت) و **بازگردانی** با شماره revision |

فهرست کامل: [docs/TOOLS.md](docs/TOOLS.md). هوش مصنوعی هنگام اتصال `instructions`، **منابع** راهنما و **promptهای** آماده (ساخت سایت، ممیزی سئو، نگهداری، انتشار نوشته، بازطراحی صفحه) می‌گیرد و می‌تواند لاگ فعالیت را بخواند.

## ایمنی در یک نگاه

| خطر | دفاع |
|---|---|
| نشت داده با کلید فقط‌خواندنی | `read` فقط داده‌ی منتشرشده و غیرحساس را می‌بیند. کاربران، سفارش‌ها، گزینه‌ها، پیش‌نویس‌ها، ایمیل نظرات و لاگ‌ها در سطح `draft`/`admin` هستند. گزینه‌هایی که شبیه رمز/کلید هستند هرگز (حتی برای admin) برگردانده نمی‌شوند. |
| حذف یا نصب ناخواسته | عملیات مخرب دومرحله‌ای است (`confirm_token` وابسته به همان آرگومان‌ها، ۵ دقیقه). حذف دائمی فقط admin. نصب از URL: admin + تأیید، فقط https، بدون redirect و بدون IP خصوصی. |
| SSRF | gateway از طریق DNS محافظت‌شده وصل می‌شود (خصوصی/loopback/link-local/metadata را لحظه‌ی اتصال می‌بندد) و redirect دنبال نمی‌کند. افزونه همین قواعد را برای دانلودها اعمال می‌کند. |
| تزریق دستور از محتوای سایت | نتایج حاوی متن سایت `content_notice` دارند؛ instructions به هوش مصنوعی می‌گوید هرگز از آن‌ها اطاعت نکند؛ HTMLِ نوشته‌شده در سطوح پایین‌تر از admin با kses فیلتر می‌شود. |
| اپ OAuth مخرب | فقط کلاینت عمومی با PKCE S256، فهرست مجاز redirect (https / loopback / editor)، صفحه تأیید **دامنه‌ی redirect** را درشت نشان می‌دهد، endpointهای ثبت و توکن rate limit دارند، مالک فوراً می‌تواند سطح را پایین بیاورد یا قطع کند. |
| سرقت refresh token | چرخش با تشخیص استفاده‌ی مجدد: بازپخش توکن قدیمی کل زنجیره را می‌بندد. |
| یک کلاینت پرمصرف بقیه را خفه کند | سطل جدا برای هر اتصال، برای نوشتن، و برای هر سایت. |
| ویرایش بد پوسته سایت را بخواباند | PHP بررسی نحوی می‌شود؛ بعد از نوشتن صفحه اول سنجیده می‌شود و در صورت خطای سرور خودکار برمی‌گردد. |

مدل کامل و محدودیت‌ها: [docs/fa/security.md](docs/fa/security.md)

## توسعه

```bash
npm test            # تست gateway (۱۰۹ تست) و افزونه (۹۴ بررسی)
npm run docs        # ساخت دوباره docs/TOOLS.md از spec/ops.json
```

`spec/build-spec.mjs` تنها منبع حقیقت برای همه‌ی عملیات است (سطح، آرگومان‌ها، تأیید). `scripts/sync-spec.mjs` فایل `ops.json` را به gateway و افزونه کپی می‌کند و یک تست در صورت ناهماهنگی شکست می‌خورد.
